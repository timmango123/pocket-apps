# 摺線（foldline）修正紀錄

## 重要發現：原版後段其實有捷徑
重寫路線規劃後發現：U 形彎彼此相鄰、誘餌紙片又多半「看起來接得上」，所以幾乎每關都有比預設路線短很多的接法（原版 L99 參考解 125 步，實際 17 步就能接通；L100 104 → 23）。原本的熟練/普通 bot 只沿路徑一格一格接，所以全滅；改成「看整個盤面規劃路線」的 bot 在原版上反而輕鬆過 L75/L99（熟練 7/7）。所以除了寬裕量和復原，也重排關卡，讓實際最少步數穩定上升。

| 發現 | 修改 | 重跑結果（修正前 → 修正後） |
|---|---|---|
| 高：L94–L100 寬裕量 0 | `apps/foldline/index.html:263` 第 11 關起寬裕量 round(5 + 9·(1−p)^1.1)：L11 14 步 → L100 5 步（原本 11 → 0）。第 1–10 關不變（12–30）。`:338` 上限 = 參考解 + 寬裕量。 | L99 上限 − 參考解：0 → 5；L100：0 → 5。 |
| 中：沒有復原，從 L10 起全部失敗 | `:142` 加「復原」按鈕（鍵盤 z / Backspace）；`:579`、`:616` 記錄每一下；`:623` undoMove() 把紙片轉回並退回一步（不扣步數）。 | 熟練 1/7 → 6/7（只剩 L100 ✘）；普通 1/7 → 4/7（L1–L50 ✔，L75 起 ✘）；手殘 1/3 → 1/5（L10 起仍全敗）；世界級、非人 7/7 → 7/7。 |
| 中：紙片 40–45 px 容易誤觸 | `:438` 左右只留 0.4 格放旗子與小屋（原 0.55），`:88` 手機上 #app 左右 padding 12 → 6 px。 | 390×844：8 欄 40 → 42 px，7 欄 45 → 48 px。誤觸仍有，但復原會把步數還回來。 |
| 低：par 不是最少步 | `:349` shortestRoute()：依紙片可轉的方向做 Dijkstra（同一張紙片不重複使用），再實際模擬確認接得通；par = min(預設路線, 最短接法)。`:328` 能組成捷徑的誘餌紙片改成釘住。`:254–257` 第 11–100 關依實際最少步數重新排序（src 記住原序號，打亂種子不變，每關內容固定）。`:338` 時限 = par × 每步秒數 + 每格 0.5 秒看盤面 + 3。 | 參考解 L75 80 → 41、L99 125（實際 17）→ 80、L100 104（實際 23）→ 83；第 11–100 關 par 由 9 穩定升到 83。 |
| 低：穩定性 | — | 0 個 console/page error。 |

## 同一個新 bot 在原版與修正版的比較
| 等級 | 原版（新 bot） | 修正版 |
|---|---|---|
| 手殘 | 1/3（L1） | 1/5（L1） |
| 普通 | 5/7（L50、L100 ✘，L75、L99 ✔，忽難忽易） | 4/7（L1–L50 ✔，L75 起 ✘） |
| 熟練 | 7/7（L99 只用 23/125 步） | 6/7（L99 84/85 ✔，L100 ✘） |
| 世界級 / 非人 | 7/7 | 7/7 |

bot 的修改（`qa/skill-tiers/foldline/bot.js`，因為遊戲多了復原）：普通/熟練看整個盤面規劃路線（每格有估計誤差，摺痕紙片有時會判斷錯），走錯就按復原；手殘從路徑前端一格一格試，偶爾用復原；世界級/非人照最短接法。舊模型就算步數無限也解不出 L10 以上，所以原版也用新 bot 重測一次。

注意：橫向（844×390）時盤面仍很小（約 16 px），原版就是這樣（五線譜和按鈕佔掉高度），這輪沒改。
