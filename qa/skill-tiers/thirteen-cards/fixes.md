# 十三支 thirteen-cards：修正紀錄

1. **［中］「一般」和「高手」幾乎一樣難。** 修正前的大樣本模擬（每格 300 局，每局分數為你對三家的合計）：普通玩家對一般 −3.06、對高手 −3.31；熟練對一般 −0.40、對高手 −0.61。兩個難度只差 0.2～0.3 分，難度選單形同虛設。
   → `apps/thirteen-cards/index.html` 核心 `plan()`：一般電腦大多數手牌照舊平衡三墩，但有 45% 的手牌（由種子決定，可重現）會像新手一樣只顧尾墩（`MIX = 0.45`）。說明頁的難度描述也一起改了。
   → 修正後的數字見 notes.md 的「修正後」表格。普通玩家對一般從 −3.06 變成 −0.27（先試跑 200 局），剛好落在新手（+1.9）和高手（−3.3）中間。

2. **［中，觸控］連點時，滑動中的牌會擋住目標。** 交換後兩張牌要滑 0.28 秒才到位。這段時間點下一張牌，手指可能落在飛過去的牌上，或落在兩排之間的空隙，結果選錯牌或沒選到。24 次一組、每秒 8 下的連點測試中，偶爾少一次交換（23/24）。
   → 滑動中的牌不接收觸控（`.cd.fly`）。點擊改用 `visualCardAt()` 判斷，以牌目前畫在哪裡為準：手指下有好幾張牌時，取中心最近的那張；點在空隙時，先找最後排定的位置，再找半張牌距離內還在滑動的牌。滑動時間縮短為 0.22 秒。
   → 修正後，連點測試跑 20 組、共 480 下，沒有漏掉，也沒有重複（`demo/verify.js`，以及 scratchpad 裡的 rapid.js）。

3. **［低，測試工具］** 非人在選中一張牌、緊接著點下一張時，有幾次被算成「點錯」。原因和第 2 項相同（點到滑動中的牌）。修正第 2 項後，這個情況也一起消失了。

## 第二輪（發布審查之後）

4. **［中，難度］「一般」是兩種玩法硬拼起來的，不是中等程度。** 第 1 項的做法是讓 45% 的手牌完全照新手排，結果一般電腦一局像新手、下一局像高手。偷懶的那些手牌也從不報到（336 次裡 0 次），因為新手排法沒有回傳 `ev`，`aiDeclare` 永遠是 false。
   → `plan()` 不再切換整手。一般電腦每手都用同一種「普通玩家」的排法（核心裡的 `weakScore`）：只算預期贏幾墩，不算加分和打槍；頭墩權重 0.3、中墩 0.6、尾墩 1，也就是太看重尾墩；每種排法的評估再加一點由種子決定的偏差（±0.6 墩）。
   → `aiDeclare`：新手和一般拿到特殊牌型一定報到；缺少 `ev` 時也會報到。
   → 說明頁改成「每手都會想辦法多贏幾墩，但太看重尾墩、輕忽頭墩，也不會算加分和打槍，判斷常有點偏差。拿到特殊牌型一定報到。」
   → tests.js 新增：一般 40/40 報到一條龍、40/40 報到六對半；60 手裡和新手排法完全相同的少於 15 手。實際開牌時，頭墩烏龍 J 以下 3%、一對以上 39%（新手分別是 53%、11%）。
   → 重新跑了一般那一欄（每格 300 局），數字見 notes.md。

5. **［低，深度］建議牌型第一種就接近最佳，自己排沒有動機。** 現在建議會依序給出最多四種想法不同的排法：平衡（預期得分最高）、穩尾墩、衝頭墩、拚打槍（三墩全贏的機會最高）。每一種都會附上「每家預估贏幾墩」和「打槍機會」，內容相同的排法會合併。要選哪一種由玩家決定。tests.js 也會檢查每一種排法，在它自己的目標上確實最好。
